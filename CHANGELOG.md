Identity (heading id) isn't tied to a fixed side of a split — it stays with whichever resulting paragraph contains the first character of the paragraph's *original* pre-edit content; the other one is treated as new and gets a freshly minted id. `insertText`, `insertPageBreak`, `insertSectionBreak`, and `insertTable` (all of which split a paragraph before inserting) now compute this per split.

Added `bulletAlignment` to the glyph fields `listPresetInfer` compares (distinguishes presets like `NUMBERED_DECIMAL_ALPHA_ROMAN`'s right-aligned roman-numeral level from otherwise-similar numbered presets).

Style patches no longer leak between characters that shared a style object. `src/core/model/apiFacts.ts` holds the recorded constants; `blankDoc.json`/`blankTab.json` are the recorded blank templates (`FakeGoogle.createDocument` now uses the former). `docModelsCompare` now also compares a tab's leading section style and table column properties, and names the differing fields.
- v2 core (not wired): `src/core/diff/` — `myers.ts` (`diffHunks`: minimal, deterministic edit hunks; `lcsPairs`: longest common subsequence with ties going to heavier, e.g. anchored, elements) and `unified.ts` (`unifiedDiffFormat`). `src/core/model/symbols.ts` views a paragraph as one symbol per code point or atom. `src/core/model/edit.ts` adds the first editing primitives: insert and delete blocks (with tombstones and structural renormalization), splice paragraph content (inserted text inherits its neighbor's style; new chips are validated; atoms can't move), and restyle text (with a `where` filter on explicit values) and paragraphs (heading ids and bullets follow the API's rules). `src/core/model/errors.ts` holds the core's typed `CoreError`.
- v2 core (not wired): editing primitives B. `src/core/model/editLists.ts` gives paragraphs list membership by the joining rules (join the previous list when compatible, else the next, else a new list with the kind's default preset), with explicit indents and bullet text style; it refuses headings, empty items, and typed bullet prefixes, reports when a nesting or kind change can't keep a custom list's look, and changes presets only on lists created this run. `src/core/model/editTables.ts` creates tables (with the API's default styles and widths), inserts and deletes rows and columns (copying the reference row's or column's styles), merges (only into an empty rectangle) and unmerges cells, styles cells, rows, and columns, pins header rows, and inserts section breaks and page-break paragraphs, adding a fresh paragraph before new tables and section breaks where the API needs one.
- v2 core (not wired): `src/core/model/copy.ts` copies blocks between tabs or documents: styles are flattened so copies look the same under the target's named styles, chips and public images are recreated, each list run becomes a new list, and links to headings copied along become pending links (cross-document links become Docs URLs); content the API can't recreate is refused unless forced, then dropped with a note. `paragraphAssign` rewrites a paragraph's content with the fewest edits so images stay. `src/core/reconcile/paragraph.ts` turns an edited paragraph into minimal requests (a code-point diff; inserted text gets its full style, kept text only changed fields; links always list underline and color so the API adds no link chrome; links to headings created this run are deferred). `RequestBuilder` gained tab-scoped v2 builders. `docModelsCompare` treats a missing `namedStyleType`/`direction` as the API's defaults, lets a paragraph that just became a heading take any minted id, and matches new chips by what they were created with.
- v2 core (not wired): `src/core/reconcile/container.ts` reconciles a whole tab body or table cell: blocks are aligned by key and each gap of deleted and new paragraphs becomes requests placed where the API leaves neighboring headings and their ids alone (new paragraphs go in at the start of the next kept paragraph, or after the previous one when there's no paragraph after or they continue its list; a deleted paragraph's undeletable newline is reused, and merges keep the surviving paragraph's state as the API does). New paragraphs get their full styles, drop inherited bullets they shouldn't have, and page-break paragraphs are supported. Kept tables have their cells reconciled. `testHarness.ts` runs edit → reconcile → emulate → compare for differential tests.
- v2 core (not wired): the reconciler now handles lists, tables, and section breaks. `src/core/reconcile/lists.ts` is a bullet pass run after content: joining the previous list is one request; new lists and anything the API can't do directly (nesting changes, joining at a deeper level) rebuild the list's whole run and are reported (a list the API would merge into its same-style predecessor is refused); removals restore final indents. `src/core/reconcile/tables.ts` inserts new tables (filling cells, then merges, widths, styles, and header rows against the API's defaults) and reconciles kept ones in a fixed order (cell content, row/column deletes, inserts, new-cell fill, merges, styles computed against what the API copies into new rows and columns). New tables and section breaks reuse the empty paragraph the API splits off before them; kept section breaks get only their changed style fields.
- v2 core (not wired): `src/core/reconcile/reconcile.ts` plans a whole document (`docReconcile`): every tab's content and bullets, its first-section and document style, tabs to create (content planned against the blank tab), and tab deletes, renames, and moves. `docPlanSelfCheck` replays the plan through the emulator and compares the result with the intended model, so a plan that wouldn't produce it is never sent. A seeded fuzz test (2,000 documents × up to 8 random edits; 20,000 verified once) found and fixed: new tables and section breaks now always follow a new paragraph and new page breaks are always followed by one (the model keeps this after later edits); page breaks and hidden (merged-over) cells can't be edited into states the API can't produce; new rows and columns never inherit a merged cell's spans (model and emulator; confirmed by two new live conformance scenarios); tables whose rows or columns are all replaced add the new ones before deleting the old; and paragraphs split off a list item inherit its bullet as it was before the bullet pass.
- v2 core (not wired): markdown lens foundations. `src/core/lens/anchors.ts` gives every block a stable anchor (headings by heading id; other blocks by the governing heading plus a short hash of their text, so restyling doesn't change them; cells by table and position) and resolves anchors, heading titles, and ranges (a node, a run of nodes, a cell, a section, or the whole tab), with nearby candidates when an anchor no longer matches. `src/core/lens/project.ts` projects a tab into lens blocks: headings, paragraphs, list items with their groups, code lines (monospace paragraphs, bridging blank lines), plain or read-only tables, and position tokens numbered per kind; empty paragraphs are owned by the block before them; emphasis is relative to the tab's most common style for each named style, with everything else named as a style directive (ignoring link chrome and code fonts).
- v2 core (not wired): `src/core/lens/render.ts` renders a projection as markdown: markdown syntax in text is escaped (line-start syntax only where it would start a block; `{{` and `::name[` so they don't read as tokens or directives), emphasis nests in a fixed order with whitespace kept outside delimiters and any style CommonMark wouldn't parse dropped, code spans and fences outgrow their backtick runs, links point at headings by unique text (else id), tabs, bookmarks, or URLs, adjacent separate lists alternate markers, and frontmatter lists sorted keys and style directives. `src/core/lens/export.ts` exports a tab or range with notes on read-only tables and (in plain mode) dropped styles.
- v2 core (not wired): `src/core/lens/parse.ts` parses lens markdown (frontmatter validated with the `yaml` package, now a dependency; CommonMark + GFM via marked without bare-URL autolinks; position tokens and style directives) into lens blocks, resolving links to headings, tabs, bookmarks, same-document URLs, and headings that exist only in the markdown, and refusing what the lens can't represent (block quotes, HTML, rules, multi-paragraph or block-holding list items, checked items, non-https images, unknown tokens, undefined directives). `canonical.ts` gives the form written-back markdown is compared in. The renderer now checks every styled block by lexing it back (in its real context: paragraph, list item, or table cell) and renders it plain when the styling wouldn't survive, so text always round-trips; tabs render as `&#9;` (the one entity the parser decodes), every `{` is escaped, and spaces next to line breaks and nesting deeper than one level below the previous item are normalized away. A seeded property test (2,000 adversarial projections; 20,000 verified once) checks text is kept, no styling is invented, and re-rendering is identical.
- v2 core (not wired): markdown write-back. `src/core/lens/put.ts` (`markdownPut`) writes markdown at a placement (replace a range, insert before/after a block, append): it aligns the range's current markdown with the new markdown block by block (`blockDiff.ts`: exact matches first, anchored blocks winning ties, then similarity pairing so an edited paragraph pairs with its edit), edits paired blocks character by character through a map that keeps content the markdown hides, changes heading levels, list kinds, and nesting in place, and creates new blocks styled like their neighbors. Unchanged markdown changes nothing; frontmatter must match the document, tab, and revision; token labels can't be edited; moving an atom recreates it when the API can (chips, public images, page breaks) and is refused otherwise; links to headings created in the same markdown point at them; appending absorbs trailing blank paragraphs. Numbered steps with bullet details (and vice versa) become a list with its own nested list, which the bullet pass can now create. Base styles now keep emphasis relative to the named style (only font, size, weight, and color follow the document's most common values, ignoring code), so they stay stable as content changes. Lens laws are tested on 15 documents (writing back unchanged markdown changes nothing, in both modes) and 500 seeded edits (what you write reads back the same, and every plan passes the emulator self-check; 20,000 verified once).
- v2 core (not wired): tables in markdown write-back. `src/core/lens/tableAlign.ts` lines up a table as read with the table as written (columns by position, or by header when the count changes; rows by content, then similarity), refusing columns whose shared header makes the change ambiguous. Editing a simple table's markdown now edits the document table: added and removed rows and columns, character-level cell edits, filled new cells, and column alignment; a table whose columns all change is recreated. Tables markdown can't show (merged cells, several paragraphs in a cell) are refused when changed or moved. The lens laws now cover table edits (5,000 seeded edits verified once), and a local-only corpus test checks write-back on every cached document.
- v2 core (not wired): loading, queries, and the pre-send guard. `src/core/engine/load.ts` loads documents through the snapshot cache (or the API) and their live comments (entities decoded), and finds every place each comment's quote occurs. `src/core/lens/query.ts` gives a tab's heading outline and per-node summaries (kind, section, list, colors, uniform style, cells, markdown, and flags such as commented, linked heading, suggestions, styled, unrecreatable). `src/core/engine/guard.ts` lists what a plan would break that can't be restored: deleting commented text (every occurrence of a repeated quote counts; touching part of it warns), content with pending suggestions, headings or tabs other content links to (deleted, un-headed, or re-identified; a replaced heading whose id moves to new content warns), named ranges, equations, rules, footnotes, drawings, Drive-only images, tables of contents, section breaks, floating-object anchors, lossy list rebuilds, and writes to documents not loaded with suggestions inline. Global `force`, or the causing step's own `force`, waives a finding.
- v2 core (not wired): the core session. `src/core/engine/types.ts` defines the API the step layer calls (sessions, document/tab/table handles, `changed` flags). `src/core/engine/session.ts` (`CoreSession`) opens documents once per run (or creates them blank or as copies, with provisional ids), and its handles edit only the in-memory model: markdown write-back and export, copying ranges across tabs and documents, find/replace, text and paragraph styles (optionally only on matching text or runs with given values), bullets, section and page setup, tab create/rename/move/delete (title-unique), table operations, and rename/lifecycle/permission intents; later queries see earlier edits. `src/core/engine/plan.ts` (`planBuild`) plans every document, proves each plan against the emulator (refusing to go on if it wouldn't produce the intended document), loads comments only when a plan deletes text, runs the guard across documents, and diffs every changed tab.
- v2 core (not wired): transactions. `src/core/engine/transaction.ts` (`transactionRun`) runs a program against a fresh session, plans and checks it, and (unless dry, or refused by unwaived guard findings) sends it in phases: create (new documents via Docs or a Drive copy, new tabs), then a re-run of the program against the real ids; content, in revision-locked chunks chained through each response; tab operations; links to headings created this run (found at their planned places in the reloaded document); then renames, permissions, and trash/delete. A revision conflict before a document's content lands reloads and re-runs the program (documents that already landed are pinned and must plan the same content again), backing off before giving up with `concurrentEdits`; a later failure reports what landed and, from the API's `requests[N]`, which step failed. After sending, each document is reloaded and checked against the plan (skipped when someone else edited it meanwhile) and cached. `FakeGoogle` now reports the current revision on every read and names failing requests the way the API does.
- v2 core (not wired): live end-to-end suite (`tests/integration/v2Live.test.ts`: fixture write-back, rich new documents, markdown edits, tables, cross-document copy, tabs and page setup, same-run heading links, a conflicting edit mid-run, dry vs live shapes) and the v2 section in `docs/architecture.md`. It found and fixed: re-applying a paragraph's own named style resets its text styles (paragraph styles now go first, and an unchanged named style is never re-sent); cell paragraphs reject `pageBreakBefore`; column widths need their width type; unbulleting a nested item leaves 36pt per level of indent, which bulleting adds to the nesting (new and rebuilt items go in unindented); a different kind of list can't be nested inside another, so nested markdown items now take their list's kind with a note (replacing the separate nested list); rich links must point at Google Drive files; ISO page sizes are exact millimetre conversions; colors compare at float32 precision; dangling heading links survive write-back; and tabs made by the create phase stay hidden until the re-run's `tabCreate` claims them. New conformance scenarios record each rule; `GDOCSMITH_ONLY` records a subset.
- The fragile-node guard now also refuses removing or rewriting a paragraph containing an inline image (in-place `innerText` is exempt and keeps the image), a horizontal rule, or a footnote reference, and refuses removing a table whose cells hold images — all without `force: true`. Previously only equations, smart chips, and Table of Contents were protected, so `replaceSection`, `replaceMarkdown`, `replace`, and `remove` could silently destroy images, dividers, and footnote text the Docs REST API cannot recreate. `query`'s `unsafeOnly` filter and node `lossWarning` summaries now flag these too
- `tests/integration/mcpWire.test.ts` now runs its whole suite against both the TS source (`bun src/index.ts mcp`) and the built Node bundle (`node scripts/mcp.mjs mcp`), so a bug introduced only by bundling (or only exercised under `node`, which is how both Claude and Cursor actually launch gdocsmith) no longer slips past `just check`
- `just argsbarg-local` and `just argsbarg-published <version>` recipes for developing against a local `../bun-argsbarg` checkout and switching back to a published release

### Changed
- `src/commands/{run,status}/__generated__/` is no longer committed (it was accidentally tracked; AGENTS.md already documented it as gitignored). `build`, `test`, `typecheck`, `release`, and (transitively, via `build`) `test-live`/`test-wire` now depend on the `schemagen` recipe, so the schema is always regenerated fresh instead of relying on a possibly stale committed copy
- `sectionCopy` without an anchor appends to the end of the target tab when it lacks the source heading (previously failed)
- argsbarg `^7.1.1` — MCP tool errors now arrive in full (previously truncated to the first line, hiding recovery hints like "pass force: true" or the list of near-miss candidates on an unresolved anchor)
- argsbarg `^7.1.2` — a schema validation error inside one step's `kind`-discriminated union (e.g. an unknown or misspelled step kind) now reports one targeted line (`unknown kind "x" (expected one of: …)`) instead of the previous 100+ line dump of every branch's unrelated errors; the MCP server also negotiates protocol version per request (was pinned to `2024-11-05`) and warns on stderr at startup if any tool definition would be truncated by Claude Code or Cursor's per-tool read limits. Known: `examples/mcp-plugin/scripts/mcp.mjs` still embeds argsbarg's pre-negotiation protocol code; out of scope for gdocsmith

### Fixed
- `DocCache.get` returned an uncloned snapshot on a SQLite cache hit (both the fresh and stale-revalidating branches), and every in-flight in-memory dedupe caller shared one Gdoc instance. In the long-lived MCP server, a dry run's in-place tape mutation of that shared object could poison what a later, unrelated live write would compile against. Both paths now return an isolated `structuredClone`, matching the memory-cache and hard-validate paths, which already cloned

## [1.0.6] - 2026-09-23

### Removed
- `allowNoop` on mutation steps. It was added alongside the no-op rejection as an escape hatch for re-running a partially applied script, but batches are atomic — a failed batch writes nothing, so a re-run starts clean and produces no no-ops. The case it existed for cannot occur, and it cost seven schema fields (~2% of the input schema, paid on every tool-schema load) to suppress the very signal the rejection exists to give. A step that changes nothing is now always an error

### Changed
- `textReplace` returned `ok: true` when its `find` string was absent, having replaced nothing — the one missing-target case that stayed silent while `query`, `replace`, and `replaceMarkdown` all rejected. It now rejects on zero occurrences, using the `occurrencesChanged` count the replace helpers already returned and the handler discarded
- `QueryTextStyle` now covers the whole Docs `TextStyle` resource — `backgroundColor`, `baselineOffset`, `bold`, `fontFamily`, `fontWeight`, `link`, `smallCaps`, `strikethrough`, and `underline` join the original `fontSize`/`foregroundColor`/`italic`. It previously reported three properties, so a query could not tell a caller that a paragraph was bold, and `DomWriter.setStyle` had nowhere to record one. Queries are correspondingly more faithful, and node checksums (hence `scopedId` values) shift for styled nodes; ids are recomputed per parse and never persisted, so nothing needs migrating
- `DomWriter.setStyle` now mirrors every run-chrome property onto the working tape, and `cellBackground` on a table node fills every cell per its documented contract, so a later step in the same batch reads the restyled state. Default-dropping moved into a shared `queryTextStyleNormalize` used by both the parser and the writer, so a mirrored patch and a re-read cannot disagree
- Table cell summaries report `backgroundColor`; cell fill was previously invisible to queries

### Fixed
- Two more `applyScript.test.ts` cases reached the network under `dryRun` and intermittently timed out after 5s — `docOpen`/`docClose` opened a nonexistent document id, and the raw-doc-ID resolution case opened a live hardcoded document (the same hazard 1.0.4 fixed for a sibling test, missed here). Both now use in-memory fixtures and run in ~27ms

## [1.0.5] - 2026-09-23

### Fixed
- `DomWriter` recorded bullet restyles and table row/column operations without mirroring them onto the working node tape, so a later step in the same batch — a query, or a mutation resolving a cell scoped id — read the pre-mutation shape. `setBulletPreset`, `insertTableRow`, `deleteTableRow`, `insertTableColumn`, and `deleteTableColumn` now update the tape the way `setNamedStyleType` and `remove` already did. Compilation is unaffected: it resolves every range from `originalNodes()`, not the working tape

### Added
- `contains:` query matches now echo a `match` snippet windowed around the hit with the matched substring bracketed (`…is more effi[ci]ent…`). `contains` is an unanchored case-insensitive substring match, so a short term like `"ci"` silently matches "efficient" and "decisions"; the result previously showed only node ids and previews, giving no way to notice the search term was wrong
- `allowNoop: true` on mutation steps, to accept a step that intentionally changes nothing

### Changed
- Mutation steps that change nothing are now rejected instead of returning `ok: true`. A write that produces no change means the anchor resolved elsewhere, the content already matched, or an earlier step in the batch applied it — reporting success made a silent miss indistinguishable from a real edit, which pushed callers into re-reading the document after every write. Detection compares a content fingerprint of the working node tape before and after the step. Steps carrying `style` or `runs` are exempt: character-level styling compiles straight to batchUpdate requests without being mirrored onto the working nodes, so the tape cannot see it and a real restyle would be misread as a no-op. The exemption suppresses only the check — the requests are still emitted and applied
- Filtered `output: "nodes"` queries are now rejected when the serialized result exceeds ~20k characters, and the error lists the first five bracketed match snippets. Filtered queries had no cap at all (only unfiltered reads truncate via `liveDump`), so `full: true` plus an over-broad filter could return far more than a caller could read — and the resulting failure said only that the response was too large, never which term overmatched

## [1.0.4] - 2026-09-23

### Added
- Everything
- `forceFetch` option on `docOpen` and `docCreate` (`fromDoc`) to bypass the document snapshot cache for guaranteed-fresh reads when a doc may have changed outside gdocsmith

### Fixed
- `applyScript.test.ts`'s multi-tab `docOpen` coverage hit a live, hardcoded Google Doc over the network instead of a mock client; replaced with an in-memory fixture so the test no longer depends on that doc's mutable tab structure or on live credentials
- Bullet/numbered paragraphs built via `elementCreate` had no default paragraph style, so they inherited whatever `spaceAbove`/`spaceBelow` the surrounding prose carried at the insertion point — producing large visual gaps between list siblings despite correct numbering. Fixed at the shared `elementCreate` primitive (not just the markdown path) so every current and future caller (markdown lists, direct `surgical` bullet inserts) defaults to tight `spaceAbove: 0, spaceBelow: 0`, unless the caller supplies an explicit override
